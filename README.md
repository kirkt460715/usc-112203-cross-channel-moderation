# 赛事跨频道互动的观看伤害计量与值守干预

样本内容用代号表示。房间及词种均为演练标识，适用负荷按当班资格和有效时段。

records 保存可离线使用的合成业务记录。每行一个 UTF-8 JSON 对象，id 在各数据表内唯一，跨表键沿用业务记录中的标识。catalog.json 保存行数及原始文件校验值。

| 记录 | 业务含义 |
| --- | --- |
| rooms.jsonl | 语言以值班覆盖资格为准。 |
| posts.jsonl | 同赛段分钟为半开区间，引用有自己生效时间，未知引用不当成没有引用。 |
| visits.jsonl | viewer 为有证据关联的观众，时间以该赛段为坐标。 |
| coverage.jsonl | 概率表示当期抽样覆盖。observed=false 表示台账缺失。 |
| reviews.jsonl | 申诉可以撤销对具体内容的标签，未审阅没有正式结论。 |
| shifts.jsonl | 值班员服务语种和承诺。基础最低在岗以房间语言为单位。 |
| policies.jsonl | 认领的干预窗口有实际起止，交接时保持房间最低要求。 |
| comparison_windows.jsonl | 名单分配于 assigned_part，跨房共用实际从 actual_part 开始。独立观测按房群与时段保留。 |
| joint_actions.jsonl | 对照保留约定与联合干预生效范围。approved=false 代表候选；修改对照约定须确认。 |
| effect_policy.jsonl | 保护的触发标准和证据范围由当班表登记。 |

## 核对资料

运行环境为 Python 3.11，使用标准库，无需下载依赖。用 `python3 -m unittest discover -s tests -v` 核对发行资料的完整性与约定的输入关系。

## 巡查滚动分析

`analysis/` 提供可在巡查期间滚动更新的分析，`report.py` 为入口：

```
python3 -I report.py --records records [--as-of N] [--format text|json]
```

- `--as-of N`：只采纳第 N 段（含）前记录的复核结论，用于逐段复盘；默认最新。未审阅内容始终显式记为"未判定"，不当作安全。
- 报告含十节：各房各段暴露（显害/溢出/未证实路径/未判定分列）、语言环境段暴露、跨房重复看到同一有害链的观众、主房基准观众群暴露去向、覆盖可比性警示、试行效果（仅独立覆盖段，被污染段标为仅安全巡查）、人力缺口与承诺一致性、候选联合干预评估、申诉影响、干预状态清单（暂停/保留巡视/推迟裁定，均带人员覆盖与观察范围）。

关键约定：

- 引用链分已知与未证实（uncertain）两类；未证实路径与未判定内容单独成桶，既不并入已知传播也不当作没有引用。
- 受理较多的房间复核密度更高：覆盖率变化的单元只可用率比较，observed=false 记台账缺失并排除出对比。
- 效果只在试行名单保留的独立覆盖段上估计；对照房被联合干预或实际领到相同措施的段仅作安全巡查证据；可比段不足 `effect_policy.minimum_comparable_parts` 时推迟裁定，不用全局平均替代。
- 申诉撤销只重定被撤销帖及其已知链下游；其他房间的独立有害来源仍然成立，联合干预不因此自动结束。
- 值班调度受语种、轮值与锁定承诺约束；候选共管须保住 keep 对照的最低独立段，或显式放弃对应试行结论后方可批准。
